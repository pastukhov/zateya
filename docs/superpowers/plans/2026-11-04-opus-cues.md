# Opus Cue Storage and Playback Implementation Plan

> **For agentic workers:** Use the executing-plans workflow; implementation is delegated to Sol, parent independently reviews and releases.

**Goal:** Download and persist compressed Opus cues and decode them incrementally for playback, reducing network, flash and resident RAM use.

**Architecture:** Preserve legacy PCM endpoints and files for old firmware. Add explicit versioned Opus negotiation to the cue API, a bounded packet container and compressed LittleFS records. Decode one bounded frame at a time through Espressif's Opus decoder; retain the existing audio owner, backpressure, drain and cancellation behavior. User explicitly said act; no additional design approval is required.

**Tech Stack:** Python backend, libopus encoder (system libopus0, ctypes binding or equivalent small maintained binding), ESP-IDF/esp_audio_codec pinned version, LittleFS1.23.1, native C/pytest.

**Spec:** This document records the agreed Opus transition and implementation design.

## Global constraints and choices

- Scope is the fourteen fixed spoken cues, not user recordings or full conversational TTS answers.
- Opus mono24kHz,24kbps,20ms frames; preserve exact source duration with encoder lookahead/pre-skip and final trimming. Decoder output remains PCM16 mono24kHz.
- Prefer a tiny versioned length-prefixed raw Opus packet container over implementing a general Ogg parser on the MCU. Document its exact byte format. This is compressed Opus audio, not a standard .opus/Ogg file; use a distinct extension/media type.
- Bound encoded bytes (64KiB), decoded samples (120000), packet bytes (1275), packet count and per-tick work. Reject inconsistent metadata, unsupported channels/rates/version, truncation, trailing junk, zero/oversized frames and impossible duration/pre-skip before playback.
- Keep compressed bytes in RAM and LittleFS. Never decode the entire catalog to persistent PCM buffers. A small per-player PCM frame buffer and one decoder instance suffice. No filesystem/network operations in audio ticks.
- Preserve PCM fallback and read old VCUEPCM1 records on upgrade. New records explicitly identify codec/version; never interpret compressed bytes as PCM. Atomically replace only after validation; retain old valid content on download/store/decode failure. No flash partition changes or reformatting.
- Keep independent pending-disk retry and storage/voice/OTA gating from OTA25. Respect acquired buffer lifetime, release exactly once on success/error/cancel/rejected start, and partial I2S writes before decoding next frame.
- Backend PCM routes and digest/version behavior remain compatible with OTA<=25. New firmware explicitly requests Opus, never silently assumes codec. Validate hash of compressed representation and metadata. Keep authenticated allowlisted nginx routes.
- Encode off HTTP request path; generate Opus from existing verified cached PCM without re-synthesizing speech. Encoder failure must not disable existing PCM cues. Restart should reuse valid disk caches.
- Avoid linking unused codec families/encoders into firmware; inspect pinned APIs locally and compile target. Build stays below3MiB OTA slot. No speech assets embedded.

## Review focus

- Encoder delay/trimming and last frame: host decode all14 samples with real libopus, exact sample counts and intelligibility/energy sanity; no lost initial syllable.
- Upgrade with old PCM files and rollback to old firmware: explicitly tagged records, bounded reads, fallback, no destructive migration.
- Malformed encoded data/decoder error: no unbounded allocation/loop, no invalid speaker bytes, decoder and cache lease released.
- Slow/zero/partial playback writes plus cancellation: queued PCM survives next tick, drain precedes completion/microphone, existing150ms settle unchanged.
- Backend mixed-version clients/cache restart/encoding failure: legacy PCM stays available; Opus is generated/reused separately and served only on explicit request.
