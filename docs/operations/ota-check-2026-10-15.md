## Резервные копии и первичная установка

Исходный полный flash backup и его SHA-256 описаны в
[USB-отчёте](usb-check-2026-10-15.md). Непосредственно перед сменой разметки
дополнительно сохранены текущие 24 576 байт NVS в
`data/device-backups/2026-10-15/7ce8b1e4b780-current-nvs.bin` (0600).
Эта копия содержит актуальные настройки с выключенным VPN;
полный более ранний backup содержит прежние настройки VPN.
Все резервные копии, образы и закрытый ключ исключены из Git.

Первый образ установлен esptool 4.11.0 по USB с проверкой хешей:

NVS `0x9000/0x6000` и PHY `0xf000/0x1000` не перезаписывались.
OTA-слоты: `ota_0=0x20000/0x300000`, `ota_1=0x320000/0x300000`.
После установки Wi-Fi подключился, backend health — 200.

Изменения для №3–5 были только в изолированной сборочной копии; намеренный
отказ самотеста не попал в исходники репозитория. Номера тестовых выпусков
не переиспользовать. Опубликован №6; тестовый №5 больше не раздаётся.

Подтверждение отката в serial-журнале:

```text
voice_ota: release 5 installed; rebooting
voice_ota: new image was not confirmed within 30 seconds
voice_ota: release 5 rejected after rollback
```

После отката прочитаны реальные записи `otadata`: слот 0, boot sequence 3,
state 2 (VALID); слот 1, boot sequence 4, state 4 (ABORTED).
Boot sequence — счётчик загрузчика, он не равен номеру выпуска приложения.
Backend увидел `current_seq=4` после возврата. При дополнительном перезапуске
устройство снова получило манифест №5, но не запросило его image: запрет
повторной установки сохранился между загрузками.

Финальный №6: журнал содержит `release 6 installed; rebooting` и
`new image confirmed by local self-test`. SHA-256 подписанного образа:
`9813323d4fcc9e816dbb48b37f0210e8762d22161477322b83850f3b16abe337`.
Таблица после установки: оба слота VALID, последний boot sequence 4
соответствует ota_1. После отдельного перезапуска backend получил запрос
с `current_seq=6` и вернул 204 (новее нет). Локальная диагностика: backend 200, Wi-Fi подключён,
VPN disabled. Старый `last_error_code=9` в диагностике — сохранённая предыдущая
ошибка; он сам по себе не означает сбой текущей OTA-установки.

## Исправление звука

OTA-самотест впервые открывает микрофон сразу после загрузки. Драйвер ES8311
в режиме BOTH при этом включает и снимает mute с DAC. Пользователь услышал
хруст и попискивание в ожидании. `open_microphone()` теперь явно заглушает
общий выход после открытия микрофона, включая возврат после воспроизведения
и ошибки открытия динамика. Воспроизведение штатно снимает mute.
Исправление: `6191db1`; целевая сборка успешна, 89/89 native tests прошли.
Физическая проверка пользователем: после обновления тихо, голосовой ответ
воспроизводится, после него снова тихо. Native tests не измеряют шум динамика.

## Ключи, сборка и ограничения

Ключ ECDSA P-256 хранится только на ноутбуке, 0600, в
`data/firmware-signing/ota-p256.pem`. На сервер переданы публичный ключ и
подписанные артефакты. Закрытый ключ на сервер не переносился.
Сборки аппаратного испытания выполнены локальным PlatformIO 6.2.0 через
`deploy/firmware/build-release.py` в изолированной копии исходников.
Работа контейнерной сборки непосредственно на сервере этим не подтверждается.

Единичный brownout выпуска №2 не повторился при дальнейших обновлениях,
но считать его причину установленной нельзя. Не выполнены принудительное
отключение питания/сети при записи flash, отрицательный тест подписи на плате,
конкуренция с записью и попытка установки без USB. Они остаются в TODO.
