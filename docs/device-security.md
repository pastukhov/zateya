# Защита диктофона и публичного API

## Сеть

Диктофон подключается к `https://zateya.atitlan.keenetic.link` без VPN.
Все исходящие HTTP-клиенты используют один TLS-адаптер: только HTTPS,
проверка цепочки сертификатов и имени сервера, запрет редиректов. Время
синхронизируется SNTP; до получения времени соединения не выполняются.
Корневые сертификаты входят в прошивку ESP-IDF; при изменении цепочки доверия
может потребоваться OTA. Отключать проверку сертификатов нельзя.

KeenDNS завершает HTTPS и передаёт запрос в LAN на порт 7071. Поэтому роутер
и локальная сеть входят в доверенную границу. Нельзя публиковать backend:7070
напрямую: внешний доступ должен идти через nginx (`alice-proxy`).

Прокси открывает только readiness, webhook Алисы и точные маршруты записи,
polling/audio, OTA, реплики «Слушаю» и диагностики. Остальные пути дают 404.
Устройство передаёт Bearer token и X-Device-Id; проверка выполняется до чтения
аудиозагрузки и повторно обработчиком. Задания привязаны к владельцу.
Ограничены методы, частота, параллельные загрузки, размер тела (аудио 19.2 MB,
диагностика 16 KiB, Алиса 64 KiB) и время бездействия соединения.
Журнал nginx содержит статус/метод/длительность без тела, токенов и query string.
Алиса сохраняет отдельную проверку OAuth-владельца и skill ID.

## Настройки и физический доступ

В setup две вкладки: Wi-Fi и сервер. Имена сетей видны; пароли, токены и
сохранённый адрес не выдаются браузеру. Пустое поле сохраняет старое значение.
Изменение адреса требует повторного ввода токена, чтобы чужой адрес не получил
сохранённый секрет. Локальный setup по HTTP не является защищённым каналом:
настраивайте устройство только в доверенной сети. Доступность setup регулируется
режимом настройки и существующими ограничениями прошивки.

NVS и flash пока не зашифрованы. Физический доступ может раскрыть Wi-Fi пароль
и токен. Secure Boot/Flash Encryption требуют отдельного испытания на запасном
устройстве; eFuse этим изменением не затрагиваются.

## OTA

HTTPS защищает передачу; дополнительно прошивка проверяет подпись P-256,
хеш, плату, размер, layout и монотонный номер выпуска. Закрытый ключ подписи
остаётся на машине сборки и не доставляется серверу. Неподтверждённая прошивка
откатывается загрузчиком. Подробности: [pull OTA](operations/pull-ota.md).

## Потеря устройства

Удалить device ID из VOICE_DEVICE_TOKENS и пересоздать backend. Проверить 401
со старым токеном. Уже запущенные задания отзыв не отменяет: проверить очередь
и изменения Obsidian. Считать Wi-Fi пароли потенциально раскрытыми, заменить
их и выдать новый токен найденному устройству. Гарантии невзламываемости нет;
это ограниченная поверхность доступа для MVP, а не аудит всей инфраструктуры.
