# Реплика «Слушаю»: серверный кэш и загрузка на диктофон

Реализовано 15 октября 2026. На StickS3 установлен OTA-выпуск №8
(исходники `92d4a12`). Загрузчик готов; распознавание слова «Затея» пока
не включено: пользовательская модель microWakeWord, задание №1279,
ещё обучается. Обычная запись кнопкой сохраняется.

## Голос и хранение

Используются обычные `TTS_MODEL`, `TTS_VOICE`, `TTS_INSTRUCTIONS` и общий
эндпоинт провайдера. После изменения `.env` пересоздайте backend:

```sh
docker compose up -d --force-recreate backend
```

Backend в фоне синтезирует «Слушаю.» один раз для данной конфигурации.
Ключ кэша учитывает текст, модель, голос, инструкции, эндпоинт и формат.
Секрет API в ключ не входит и не выдаётся устройству. Кэш хранится в
`./data/archive/device-cues` рядом с Compose, внутри контейнера —
`/data/archive/device-cues`. Перезапуск использует исправный готовый кэш;
повреждённый файл пересоздаётся. Ошибка синтеза повторяется через 60 секунд,
не блокируя HTTP обработку. Расчёт предполагает один backend-процесс,
как в текущем Compose. Старые версии кэша автоматически не удаляются.

Диктофон на внешнем питании после HTTP 200 от проверки готовности загружает
реплику в PSRAM. Повторная проверка — не чаще раза в минуту и только в
ожидании, вне OTA. Начало записи прерывает дальнейшее чтение загрузчика;
I2S он не использует. Кнопочная запись не ждёт кэш. При выключении питания
кэш устройства исчезает и загружается заново после подключения.

Новый буфер становится доступен только после проверки размера, формата и
SHA-256. Во время воспроизведения его нельзя заменить или освободить.
Если обновление не удалось, прежний исправный буфер остаётся. После смены
голоса прошивку пересобирать не нужно. До первой успешной загрузки
голосовая активация должна оставаться недоступной (гейт интеграции детектора).

## API

Оба метода требуют `X-Device-Id` и `Authorization: Bearer …` с существующим
токеном устройства:

- `GET /api/device/cues/listening`: версия, SHA-256, размер, частота,
  число каналов и разрядность. HTTP 503 с `Retry-After: 60`, пока файла нет.
- `GET /api/device/cues/audio/{sha256}.pcm`: PCM16 little-endian, mono,
  24 кГц, до 5 секунд (240000 байт). Неизвестный digest возвращает 404.

Ни один из методов не запускает синтез. Неавторизованный запрос — 401.
Загрузчик не следует перенаправлениям и не пересылает токен на другой URL.

## Проверки и пределы

- 516 backend-тестов, 97 native-тестов и 3 теста WAV-конвертера прошли.
- ESP32-S3 собран; OTA №8 установлен и подтверждён локальной самопроверкой.
- На реальном backend проверены 401 без токена, манифест/аудио с токеном,
  совпадение размера и SHA-256.
- Устройство после обновления записало в журнал:
  `cue_cache: Listening cue cached: 53760 bytes`.
- Смена голоса, повторный старт кэша, повреждение файла, единственный синтез
  при параллельных запросах и публикация буфера с читателем проверены тестами.
- Аппаратная смена голоса, прерывание загрузки кнопкой и воспроизведение
  «Слушаю» после реального wake word ещё не проверены.

Следующий этап после экспорта `.tflite` и параметров модели: аудиофронтенд,
локальный детектор, VAD, соединение с политикой записи и плеером; настройка
паузы, индикация и аппаратная матрица активации. Детектор должен брать буфер
через `voice_cue_cache_acquire` и отпускать его только после физического
окончания/отмены воспроизведения. На активации сетевого запроса быть не должно.
