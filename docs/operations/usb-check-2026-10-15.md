## Первая запись без VPN

После отключения устаревшего WireGuard backend health вернул 200. Записано,
поставлено в очередь и отправлено по 97 280 байт; peak ring 2048 байт,
peak upload 1792 байта, max write 10 мс. Сервер ответил 202, STT — 200.
Через несколько секунд устройство показало код 09: backend остановил
обработку на `Obsidian refresh blocked`, статус Git `retry`.

На сервере найдено 1209 zombie `sh` и 75 543 zombie `git`, дочерних
процессу uvicorn PID 1 контейнера. Запуск Git завершался `Cannot fork`;
непосредственная причина этой ошибки записи — исчерпание процессов.
Compose backend теперь использует `init: true`, чтобы собирать завершённых
осиротевших потомков. Изолированный smoke-test `python deploy/check-process-reaping.py`
воспроизводит восемь zombie без init и проверяет отсутствие их с init.
Тест запускается от корня репозитория после сборки образа backend.

Также старый backend возвращал 404 на `/api/devices/diagnostics`; требуется
обновление и пересоздание контейнера. Эта ошибка в LAN не доказывает
исправление прежнего переполнения при медленном мобильном VPN.

Исправление `4aec9f9` развёрнуто на сервере 15 октября, локальные серверные
коммиты сохранены merge-обновлением. После пересоздания backend: `init=true`,
4 задачи вместо примерно 76 тысяч; Git fetch успешен, `GitSync.run_once()`
возвращает `idle`, `/health/ready` — 200. Smoke-test на сервере: 0 zombie.
Повторная голосовая проверка пользователем успешна: ответ прозвучал.
