# Мониторинг и стоимость

Затея экспортирует Prometheus-метрики через локальный `GET /metrics`. Этот
адрес предназначен для доверенной сети и не публикуется через Alice/KeenDNS.

## Источник стоимости

Учёт не зависит от конкретного поставщика OpenAI-совместимого API. Backend
сохраняет стандартные поля `usage.prompt_tokens` и `usage.completion_tokens`,
длительность отправленного STT-аудио и число символов TTS-текста.

Если endpoint возвращает стоимость в JSON-ответе, её можно считать фактической
(`reported`) через явно настроенные JSON-пути. Никаких дополнительных запросов
к API поставщика backend не выполняет. Если денежного поля нет, стоимость
вычисляется по локальным тарифам (`estimated`), а без достаточных данных
остаётся `unknown`. Ошибки и таймауты также остаются `unknown`, потому что
клиент не может надёжно установить факт списания.

## Локальные тарифы

Скопируйте `deploy/pricing.example.json` в `data/archive/pricing.json` и
заполните только тарифами, проверенными на странице используемой модели.
Файл примера намеренно пуст: репозиторий не содержит условных или устаревающих
цен. Поддерживаются единицы `input_tokens_1m`, `output_tokens_1m`,
`audio_minute`, `text_characters_1m`. Денежные значения — десятичные строки;
валюты не конвертируются и не складываются.

Необязательный список `reported_costs` описывает, откуда брать фактическую
стоимость в JSON-ответе LLM или STT. `amount_path` и `currency_path` — пути из
имён полей, разделённых точками. Вместо `currency_path` можно задать постоянную
`currency`. Для одной пары `stage`/`model` допускается одна настройка:

```json
{
  "version": 1,
  "rates": [],
  "reported_costs": [
    {
      "stage": "llm",
      "model": "имя-модели",
      "amount_path": "usage.billing.amount",
      "currency_path": "usage.billing.currency"
    },
    {
      "stage": "stt",
      "model": "имя-stt-модели",
      "amount_path": "usage.cost",
      "currency": "RUB"
    }
  ]
}
```

Настройка применяется только к JSON-ответам. TTS endpoint, возвращающий сразу
аудиопоток, учитывается по числу символов и локальному тарифу.

Путь внутри контейнера задаётся `USAGE_PRICING_PATH`, по умолчанию
`/data/archive/pricing.json`. Отсутствующий файл допустим: метрики использования
сохраняются, а стоимость отображается как неизвестная.

## Сбор и дашборд

Backend отдаёт метрики на LAN-адресе `http://192.168.11.2:7070/metrics`.
Пример отдельного job для vmagent находится в
`deploy/monitoring/zateya-scrape.yml`: его нужно добавить к существующим
`scrape_configs`, не заменяя остальную конфигурацию. Интервал — 15 секунд,
таймаут — 5 секунд. Через KeenDNS `/metrics` публиковать не следует.

Дашборд `deploy/grafana/zateya.json` импортируется в существующую Grafana.
При импорте выберите datasource типа Prometheus, который указывает на
VictoriaMetrics. Дашборд разделяет каналы, валюты и `reported`/`estimated`,
показывает неизвестные расходы и дату начала учёта. Средняя цена заметки
считает только `capture`, для которых известна стоимость всех внешних вызовов;
`amend` остаётся отдельной операцией. На первом scrape VictoriaMetrics видит
только текущее накопленное значение: точную временную историю до начала сбора
восстановить нельзя.

## Что проверено

- Unit и интеграционные тесты проверяют сохранение Decimal-сумм после
  перезапуска, идемпотентность, конкурентную запись/scrape, разделение валют,
  неизвестную стоимость и отсутствие пользовательского текста в labels.
- MockTransport-тесты проверяют учёт физических LLM/STT/TTS HTTP-вызовов,
  ошибок, timeout, repair-запросов и повторов из кэша.
- JSON дашборда и отдельный scrape job проверяются автоматически.

datasource `Victoriametrics`. После импорта проверьте панели за последние 24
часа; пустая стоимость до первой реальной обработки является нормой.
