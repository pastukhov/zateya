# Затея · Zateya

Затея — голосовой помощник с двумя интерфейсами: карманным диктофоном на M5Stack StickS3 и навыком Яндекс Алисы «Моя затея». Она превращает поток мыслей в заметки Obsidian и связанную LLM Wiki, помогает развивать идеи и сохраняет планы и задания по принципу «Ramble your idea, then build».

Документация: [Русский](docs/ru/index.md) · [English](docs/en/index.md).

В проект входят прошивка и один серверный Voice Gateway. Gateway выполняет распознавание речи, обращается к настроенному OpenAI-совместимому Chat Completions endpoint, проверяет и записывает Markdown в Obsidian, синтезирует ответ и в фоне публикует изменения через Git. Codex CLI и аккаунт Codex не требуются. Все постоянные каталоги лежат рядом с Compose в `data/`.

## Быстрый запуск

```sh
cp .env.example .env
# Укажите LLM_*, STT_*, TTS_* и токены устройств в локальном .env.
chmod 600 .env
```

Для Gemini TTS укажите `TTS_MODEL=google/gemini-3.8-flash-lite-tts`, `TTS_VOICE=Kore`, `TTS_RESPONSE_FORMAT=pcm` и оставьте `TTS_INSTRUCTIONS` пустым. Gateway упаковывает PCM16 little-endian, 24 кГц, моно в WAV для диктофона. Для провайдеров, возвращающих WAV, используйте `TTS_RESPONSE_FORMAT=wav`. После изменения `.env` пересоздайте backend: `docker compose up -d --build backend`.

Для развертывания на сервере подготовьте существующий Obsidian vault в `data/obsidian`, настройте Git SSH в `data/ssh` и следуйте [инструкции для Linux-сервера](deploy/server-migration.ru.md). Для проверки конфигурации и тестов смотрите [руководство разработки](docs/development.md).

Gateway работает в стандартной bridge-сети Compose с опубликованным портом для диктофона. Ограничьте доступ к этому порту доверенной LAN/WireGuard. Значения `LLM_API_KEY` и токены устройства передаются только процессу gateway и не выдаются веб-интерфейсу диктофона.

## Подключение StickS3

Без сохранённых Wi-Fi настроек устройство поднимает открытую сеть `Zateya-Setup-XX`, где `XX` — последние два hex-символа Wi-Fi MAC. Телефон обычно предлагает открыть setup portal; если нет, перейдите на `http://192.168.4.1/`.

В веб-форме выберите Wi-Fi и укажите адрес Gateway и device token. Полный setup доступен и после подключения к локальной сети по адресу устройства или его mDNS-имени. Внизу формы есть сброс настроек с подтверждением.

Экспериментальное pull-OTA подготовлено в коде: Compose может собрать подписанный
кандидат, а устройство — проверить и скачать явно опубликованный релиз.
Для первого запуска нужны новая разметка и прошивка по USB; до аппаратной
проверки автоматическую публикацию не включайте. См. [процедуру OTA](docs/operations/pull-ota.md).

## Голосовой запрос

Устройство использует half-duplex цикл: `ГОТОВА → СЛУШАЮ → ДУМАЮ → ОТВЕЧАЮ → ГОТОВА`. Gateway сохраняет запись как задачу, обрабатывает её и возвращает WAV; каждому устройству нужен отдельный bearer-токен.

На содержательную диктовку Затея отвечает коротко, сохраняет исходную расшифровку и оформленную мысль в Obsidian, а затем коммитит и отправляет изменения в `origin`. Подробности — в [руководстве LLM Wiki](docs/voice-knowledge.md).

## Навык Яндекс Алисы «Моя затея»

Можно диктовать идеи через Алису параллельно с диктофоном. Оба интерфейса используют общий сервер, контекст и Obsidian vault: сохраняют мысли, дополняют заметки и развивают связанную LLM Wiki. Распознавание и озвучивание в навыке выполняет Алиса.

Продиктуйте мысль одним сообщением или скажите «Начни запись», добавьте несколько фрагментов и завершите командой «Закончи запись». Быстрый результат Алиса озвучит сразу; если обработка не укладывается в бюджет webhook, ответит «Приняла запись, обработаю её в фоне». Спрашивать «Готово?» необязательно, но эта команда позволяет узнать результат позже.

Сервер экспортирует метрики Prometheus по задачам, этапам, Git-синхронизации
и расходам LLM/STT/TTS. Готовый дашборд Grafana и пример настройки vmagent
описаны в [руководстве по мониторингу](docs/monitoring.md).

Навык требует привязки аккаунта через Яндекс ID и разрешает доступ только настроенному владельцу. Для публикации webhook предусмотрен профиль Compose `alice` с отдельным Nginx-прокси: через KeenDNS наружу доступен только `POST /api/alice/webhook`, а API диктофона остаётся в локальной сети.

Создание навыка, OAuth, переменные `ALICE_*`, настройка KeenDNS и диагностика описаны в [инструкции по навыку Алисы](docs/alice-skill.md).

## Структура репозитория

| Путь | Назначение |
| --- | --- |
| `firmware/` | ESP-IDF/PlatformIO прошивка M5Stack StickS3 |
| `backend/` | FastAPI Gateway, LLM/STT/TTS-клиенты, архив, Obsidian writer и Git publisher |
| `deploy/` | подготовка данных, systemd unit и прокси для Алисы |
| `docs/` | архитектура, протокол, разработка, прошивка и схемы |
| `docker-compose.yml` | backend, прокси Алисы (`alice`) и сборщик прошивки (`firmware`) |
| `.env.example` | шаблон переменных без рабочих секретов |

`.env`, Wi-Fi пароли, device tokens, API-ключи и SSH-ключи не коммитьте. Setup AP открыт и предназначен для настройки в непосредственной близости от устройства.

### mDNS

Диктофон публикует имя `zateya-<MAC>.local`, например `zateya-7ce8b1e4b780.local`. Полный setup доступен через это имя в локальной сети или через `http://192.168.4.1/` в режиме точки доступа.
