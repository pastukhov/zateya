# Затея · Zateya

Затея — карманный голосовой помощник на M5Stack StickS3: превращает поток мыслей в заметки и связанную базу знаний в Obsidian, помогает развивать идеи и готовить планы реализации. Основа — LLM Wiki и «Ramble your idea, then build».

Документация: [Русский](docs/ru/index.md) · [English](docs/en/index.md).

Проект состоит из прошивки устройства, Python-шлюза и отдельного host-сервиса для Codex. Текущая установка работает через Codex Agent и сохраняет записи в Obsidian. Ни прошивка, ни Docker-контейнер не получают доступ к Codex credentials.

![Схема компонентов и границ безопасности](docs/assets/system-overview.svg)

## С чего начать

1. [Настройте и запустите Voice Gateway](docs/development.md#запуск-шлюза).
2. Настройте [host-side Codex Agent](deploy/codex-voice-agent.md) и выберите `VOICE_AGENT_PROVIDER=codex` для сценария LLM Wiki.
   Для переноса всей системы на отдельный компьютер используйте [инструкцию по Linux-серверу](deploy/server-migration.ru.md).
3. Подключите StickS3 к Wi-Fi через [setup portal и прошейте устройство](docs/flash-sticks3.md).
4. Посмотрите [архитектуру и путь голосового запроса](docs/architecture.md), [HTTP-протокол](docs/protocol.md) или полный [указатель документации](docs/index.md).

## Быстрый запуск шлюза

Нужны Docker Compose и доступные сервисы распознавания речи, Codex Agent и синтеза речи.

```sh
cp .env.example .env
# Откройте .env и настройте endpoint’ы и модели; секреты оставьте только в этом локальном файле.
docker compose up --build -d backend
curl --fail http://127.0.0.1:8080/health/live
curl --fail http://127.0.0.1:8080/health/ready
```

Compose запускает gateway с `network_mode: host`, поэтому он может обращаться к локальным сервисам на хосте. Проверьте сетевую изоляцию перед запуском в общей или недоверенной сети; не публикуйте gateway в Internet. Остальные проверки и запуск без Docker описаны в [руководстве разработки](docs/development.md).

## Подключение StickS3

Без сохранённых Wi-Fi настроек устройство поднимает открытую сеть `Zateya-Setup-XX`, где `XX` — последние два hex-символа Wi-Fi MAC. Телефон обычно предлагает открыть setup portal автоматически; если нет, перейдите на `http://192.168.4.1/`.

Внизу setup portal есть кнопка **«Сбросить все настройки»** с подтверждением. Она удаляет все Wi-Fi сети и пароли, параметры gateway, токен и ключи WireGuard, возвращает таймер сна к 30 секундам и перезагружает устройство в режим настройки. Для повторной настройки подключитесь к `Zateya-Setup-XX` и откройте `http://192.168.4.1/`.

В веб-форме выберите сеть и укажите базовый адрес Gateway, например
`http://192.168.1.10:8080`, и device token. Выбора версии протокола нет.

Сохранённая сеть получает минуту на подключение. Если подключиться не удалось, setup AP включится, а устройство продолжит попытки соединения. При успешном подключении AP выключится. Gateway должен знать пару device ID → token; подробности — в [настройке устройства](docs/flash-sticks3.md) и [протоколе](docs/protocol.md).

## Голосовой запрос

Устройство использует half-duplex цикл: `ГОТОВА → СЛУШАЮ → ДУМАЮ → ОТВЕЧАЮ → ГОТОВА`. Состояние ошибки остаётся на экране до нажатия кнопки. Отдельная LED-индикация не используется.

Gateway сохраняет запись как задачу, обрабатывает её в очереди, а устройство проверяет состояние и скачивает WAV. Каждому устройству нужен отдельный bearer-токен.

## Важно

- Backend сохраняет голосовые запросы и результаты в archive. Проверьте путь и политику хранения перед использованием с личными записями.
- Для текущего сценария нужен `VOICE_AGENT_PROVIDER=codex`; firmware работает через единый асинхронный API.
- Setup AP открыт и предназначен только для локальной настройки.
- `.env`, Wi-Fi пароли, device tokens и Codex credentials нельзя коммитить.

### Обнаружение диктофона в локальной сети

Диктофон публикует mDNS-имя `zateya-<MAC>.local`, например
`zateya-7ce8b1e4b780.local`. Имя постоянно, не зависит от выбранной Wi-Fi сети
и сохраняется после сброса настроек. Устройства можно обнаружить через DNS-SD
по сервису `_zateya._tcp`; также публикуется `_http._tcp` (порт 80).
TXT-записи содержат модель `StickS3`, путь `/` и `access=local-wifi-and-setup`.

В Linux с Avahi: `avahi-browse -rt _zateya._tcp` или
`avahi-resolve-host-name -4 zateya-7ce8b1e4b780.local`.
Клиент и диктофон должны находиться в одной локальной сети с разрешённым multicast.
Полный веб-интерфейс доступен как в setup AP, так и в локальной Wi-Fi сети:
`http://zateya-7ce8b1e4b780.local/` или по IP диктофона.
В обоих случаях доступны сканирование сетей, сохранение параметров и сброс
с подтверждением. Вход без пароля; доступ разрешён из подсети подключённого Wi-Fi
и собственной setup-сети устройства.
Используется [компонент mDNS Espressif](https://components.espressif.com/components/espressif/mdns/versions/1.11.3/readme).

На экране значок Wi-Fi показывает наличие подключения (цветной — подключён,
серый — нет). Рядом `WG`: серый — WireGuard выключен, мигающий оранжевый —
ожидание Wi-Fi/времени или установка туннеля, зелёный — peer подключён,
красный — ошибка или конфликт подсетей. Уровень Wi-Fi сигнала значок не показывает.

При включении WireGuard автоматически используется полный IPv4-туннель.
Голосовые запросы принудительно привязаны к VPN-интерфейсу, поэтому адрес
сервера вроде `192.168.11.66` можно оставить прежним. WireGuard-сервер должен
маршрутизировать запросы в эту сеть и обеспечивать обратный маршрут или NAT.
Для интернета через VPN на сервере также нужен соответствующий выход.
Локальные подсети Wi-Fi и setup остаются доступны напрямую для управления;
зашифрованное соединение с WireGuard-сервером идёт через Wi-Fi.
Прежняя настройка отдельной галочки полного туннеля больше не используется.
