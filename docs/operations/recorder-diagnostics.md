# Диагностика диктофона без USB

Диагностическая прошивка из `7e2ea6b` установлена на StickS3 по USB
15 октября 2026 года. Запуск и чтение `/api/diagnostics` проверены на устройстве.
Проверка кодов при реальной ошибке записи и доставки отчёта на backend пока
открыта. См. [результаты USB-проверки](usb-check-2026-10-15.md).

В локальном setup нажмите **Диагностика → Обновить** или откройте
`http://zateya.local/api/diagnostics`. Кнопка **Скачать отчёт** сохраняет JSON.
Setup доступен в сети Wi-Fi диктофона или его точке доступа, но не через
публичный Alice proxy. Отчёт содержит только числовые счётчики, фиксированные
сетевые состояния и коды; речь, SSID, адрес сервера, ключи и токены в него
не попадают.

После ошибки диктофон показывает короткое русское описание и, когда не пишет и не воспроизводит
звук, пытается отправить отчёт на `POST /api/devices/diagnostics` существующим
токеном устройства. Предел — три попытки за бодрствование с паузами 5 и 15
секунд. Сервер хранит последние 20 отчётов на устройство не дольше семи дней
в `data/archive/diagnostics.sqlite`. Одинаковые `boot_id` и `sequence` принимаются
повторно без новой записи. Последний код ошибки также сохраняется в NVS и
остаётся после полного выключения питания. Подробные счётчики текущего сеанса
пока хранятся в RAM: после перезагрузки останется код, но не прежние значения
буферов. Это ограничение следует учитывать при разборе ошибки.

Коды: `02` — переполнен кольцевой буфер записи; `03` — ошибка очереди отправки;
`04` — открытие, запись или завершение HTTP-загрузки не удалось; `09` — общий
сбой голосовой задачи. События в JSON имеют вид
`[uptime_ms, code, arg0, arg1]`. Для загрузки `captured_bytes`, `queued_bytes`
и `sent_bytes` позволяют увидеть, где отстаёт передача;
`ring_high_water_bytes`, `upload_high_water_bytes` и `write_max_ms` показывают
пик заполнения и максимальную задержку одного вызова записи. Сам код `04`
не доказывает нехватку пропускной способности: нужна сверка с TCP и serial.

Для чтения серверной базы на сервере используйте SQLite локально. Например,
`sqlite3 /opt/zateya/data/archive/diagnostics.sqlite 'select created_at,payload from device_diagnostics order by created_at desc limit 5'`.
Не публикуйте полный файл базы: в нём есть идентификаторы устройств и метаданные
времени, хотя нет секретов настроек.


## Сообщения экрана (с выпуска 12)

Числовые коды сохранены в JSON для диагностики, на экране — описание:

| Код | Значение / сообщение |
|---|---|
| 02 | Буфер записи переполнен |
| 03 | Сбой очереди отправки |
| 04 | Сбой отправки записи |
| 05 | Нет времени для VPN (ожидание синхронизации часов) |
| 06 | VPN не подключился |
| 07 | Долго нет ответа сервера |
| 09 | Сбой обработки записи |

01 и 08 — события начала записи и успешной загрузки, не ошибки.
09 остаётся общей ошибкой: точная стадия определяется журналом backend.
Например, 15 октября повторный тест молчания завершился пустым результатом STT.
Для выхода из ошибки нажмите и отпустите основную кнопку.
