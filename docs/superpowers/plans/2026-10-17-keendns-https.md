# HTTPS через KeenDNS без WireGuard

Согласовано: один диктофон, MVP, обратная совместимость не требуется.

1. Удалить VPN из прошивки, настроек, интерфейса и зависимостей.
2. Все исходящие подключения устройства: только HTTPS, системные корневые
   сертификаты, проверка имени, SNTP до подключения, без редиректов.
3. Открыть через существующий nginx на 7071 только Alice, readiness и
   авторизованные маршруты диктофона: запись, polling/audio, cue, OTA, диагностика.
   Проверять токен до чтения загрузки; ограничить методы, размер и частоту.
4. Проверить native/UI/backend и настоящий nginx, собрать ESP32.
5. Установить начальную прошивку, настроить публичный URL, проверить запись
   и воспроизведение; следующую подписанную версию установить pull OTA через HTTPS.
6. Обновить документацию, независимое ревью, commit/push, выкатить на сервер.

## Журнал

- Удалены VPN-код, поля NVS/API/UI и зависимость. Старые ключи не мигрируются.
- HTTPS-клиент централизован: CA bundle, hostname verification, запрет HTTP/redirect.
- Native: 93/93; UI: 24/24; nginx Docker integration: passed.
- Целевая сборка ESP32 проходит. Физические проверки ещё предстоят.
- Решение: имя существующего сервиса alice-proxy сохранено, чтобы не менять
  настроенный KeenDNS upstream; он обслуживает оба клиента.
- Не меняем eFuse, flash encryption и ключ OTA. Это отдельный аппаратный проект.

- Backend: 519 passed; подписи/layout OTA: 9 passed; ESP32 build passed.
- Независимое ревью: разделены upload/read connection zones, квота привязана
  к credential вместо общей квоты, чтобы неверный токен не вытеснял устройство.

- Выпуск 14 установлен и подтверждён локальным self-test. На живом ESP32
  TLS выявил нехватку внутренней RAM (mbedtls -0x7F00); буферы перенесены
  в PSRAM. Требуется повторная аппаратная проверка в следующем выпуске.

- Выпуск 15: HTTPS certificate validated, readiness 200; пользователь подтвердил
  запись/ответ/«Готова». Выпуск 16 установлен самостоятельным pull OTA через
  KeenDNS, после загрузки current_seq=16, readiness 200.
